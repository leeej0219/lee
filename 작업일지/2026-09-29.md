## 실제 YouTube 채널 연동 (같은 날)

### 요청 내용

- 대시보드에서 실제 분석 데이터를 볼 수 있게 해달라는 요청.

### 확인/결정 사항
- 이 세션에서 youtube.com은 접속 차단, googleapis.com은 접속되지만 인증 없이는 403 → 실제 데이터는 구글 공식 API + 인증이 필수임을 확인.
- 사용자에게 범위를 질문 → **"비공개 분석까지 전부"**(유입 경로·검색어·구독/구독 취소·시청시간 포함, OAuth 필요) 선택.
- 구현 방식: 서버 없이 **대시보드 페이지가 브라우저에서 직접 구글 로그인(OAuth, Google Identity Services)** → YouTube Data API v3 + YouTube Analytics API 호출.
  - 비밀키·리프레시 토큰 저장이 필요 없고, Analytics API가 과거 일별 데이터를 통째로 주므로 매일 수집하는 서버(GitHub Actions 등)가 필요 없음.
  - (참고: GitHub Actions로 매일 수집하는 방식은 "테스트 모드" 앱의 리프레시 토큰이 7일마다 만료돼서 제외.)

### 진행한 작업 (`docs/youtube/index.html`)
- 설정에 "▶ YouTube 채널 연결" 카드 추가: 클라이언트 ID 입력, "구글로 로그인해서 가져오기"/새로고침/연결 해제, Google Cloud 설정 5단계 안내.
- 불러오는 데이터:
  - 채널 일별: 조회수·좋아요·댓글·새 구독·구독 취소·시청시간 → 홈 KPI/추이/월별 누적은 이 값으로 계산(정확값).
  - 영상별: 제목·썸네일·업로드일시·길이, 일별 누적 성과(업로드 후 30일은 매일, 이후 주 1회로 저장), 유입 경로(+시청시간), YouTube 검색어 TOP10, 평균 시청 지속시간, Shorts/롱폼 구분.
  - 구독자 수 기록: 일별 (새 구독 − 구독 취소) 누적으로 자동 계산.
- Shorts/롱폼 판별: Analytics `creatorContentType` → 실패 시 Shorts 피드 유입 50% 이상 또는 60초 이하. 사용자가 수정하면 그 값을 고정.
- 유입 경로 매핑: SHORTS→Shorts 피드, YT_SEARCH→YouTube 검색, RELATED_VIDEO→추천 동영상, SUBSCRIBER→탐색 기능, YT_CHANNEL→채널 페이지, EXT_URL→외부, 나머지→기타.
- 새로고침해도 직접 쓴 유형·태그·회고는 보존. 새 영상은 제목/설명의 #해시태그를 초기 태그로 사용(#shorts 제외).
- 분석 데이터가 2~3일 늦게 들어오는 점을 반영해, 연동 중에는 기간의 끝을 "마지막 분석 데이터 날짜"로 맞춤(그래프 끝이 0으로 떨어지는 문제 방지).
- 구독자 페이지: 연동 시 "새 구독/구독 취소"를 실제 값으로 표시, 수동 입력 폼 숨김. 유입 분석: 유입별 시청시간·1회당 시청 추가. 상세: 평균 시청 시간/총 시청시간 표시.
- 구글 API 응답을 흉내 낸 가짜 서버(Playwright route)로 로그인→수집→저장→화면 표시 전체 흐름 테스트, 오류 없음.

- 제안/결정: 이미 붙인 구글 로그인을 그대로 써서 **구글 드라이브 appDataFolder(앱 전용 숨김 폴더)** 에 대시보드 데이터를 저장 → 사용자 동의("응").
- 구현(`docs/youtube/index.html`):
  - 권한에 `drive.appdata` 추가(로그인 1시간 토큰을 localStorage에 보관해 창을 닫았다 열어도 1시간 안에는 재로그인 없음).
  - "↻ 새로고침" 순서: 드라이브에서 다른 기기 기록 받기 → 합치기 → YouTube 새로고침 → 드라이브에 저장.
  - 직접 수정(회고·유형·태그·아이디어·삭제)하면 로그인이 살아 있을 때 1.2초 뒤 자동으로 드라이브에 저장. 로그인이 끝났으면 "이 기기에만 저장된 변경이 있어요" 표시 → 새로고침 시 반영.
  - 앱을 열거나 다시 볼 때(로그인 유효 시) 자동으로 드라이브에서 최신 기록을 받아옴.
  - 합치기 규칙: 직접 쓴 내용은 더 나중에 고친 쪽(editedAt), YouTube 숫자는 더 나중에 새로고침한 쪽(syncedAt), 삭제한 콘텐츠/아이디어는 삭제 표시로 양쪽에 반영.
  - 드라이브 실패 시 YouTube 새로고침은 계속하고 상태줄에 원인 표시(예: Drive API 미사용).
- 가짜 구글/드라이브 서버로 "PC 연결 → PC에서 회고 작성 → 휴대폰 첫 연결 시 회고 보임 → 휴대폰에서 아이디어 추가 → PC 다시 열면 보임" 시나리오 테스트 통과.
- 사용자 할 일: Google Cloud에서 **Google Drive API 사용** 켜기, 각 기기에서 새로고침 → 권한 화면에서 "모두 선택"(항목 3개).
- 추가 수정: 반복 테스트 중 가끔 다른 기기 기록을 못 받아오는 문제 발견 → 드라이브 응답이 브라우저 캐시의 옛 사본으로 대체되던 것이 원인으로 보여 `cache: 'no-store'` 적용. 이후 6회 연속 통과.
