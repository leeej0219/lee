### 결정 사항 (사용자 확인)
- 저장 백엔드: **Firebase (Firestore)** 사용 (사용자가 무료로 구글 계정으로 프로젝트 생성).
- 접근 보안 방식: **볼트 코드** 방식 — 기기마다 한 번 무작위 코드를 입력/생성해서 연결. 코드를 아는 사람만 접근 가능(전통적인 아이디/비밀번호 로그인 없음).
- 호스팅: 이 저장소(`leeej0219/lee`)의 `docs/` 폴더를 GitHub Pages로 제공하기로 함(무료, 로그인 없이 접속 가능).

### 진행한 작업
- `docs/index.html` — Firebase Firestore 기반 메모장 웹앱 작성.
  - 온보딩 화면: "새 볼트 만들기"(10자리 무작위 코드 생성) / "기존 코드로 연결하기".
  - 생성된 코드는 `localStorage`에 저장해 다음 방문부터 자동 연결, 헤더의 코드 칩을 눌러 코드 확인/복사/연결 해제 가능.
  - 메모 목록(검색·새 메모·삭제·상대시간)과 메모 상세/편집(자동저장, 글자 수, 삭제) 화면은 기존 클로드 아티팩트판과 동일한 디자인/기능 유지, 저장 계층만 Firestore로 교체.
  - Firestore 경로: `vaults/{볼트코드}/notes/{메모ID}`.
  - Firebase JS SDK(모듈형, v10.12.2)를 gstatic CDN에서 직접 import.
- `docs/firebase-config.js` — Firebase 프로젝트 설정값을 넣을 자리(placeholder). 사용자가 값을 주면 채워서 커밋 예정.
- `docs/firestore.rules` — 볼트 코드를 아는 사람만 읽기/쓰기 가능하고, 볼트 목록 나열(list)은 막는 보안 규칙. Firebase 콘솔에 그대로 붙여넣도록 안내.
- `docs/.nojekyll` — GitHub Pages의 Jekyll 처리를 끄기 위한 빈 파일.

### 남은 이슈 / 사용자가 해야 할 일
- Firebase 콘솔(https://console.firebase.google.com)에서 무료 프로젝트 생성 → Firestore Database 활성화 → `docs/firestore.rules` 내용을 규칙 탭에 붙여넣기 → 웹 앱 등록 후 나오는 config 값(apiKey 등 6개)을 전달받아 `docs/firebase-config.js`에 반영 필요.
- GitHub 저장소 Settings > Pages에서 `main` 브랜치 `/docs` 폴더를 소스로 설정해 Pages를 켜야 실제 접속 링크(`https://leeej0219.github.io/lee/`)가 생성됨 — 이 저장소 설정 화면 접근 권한이 필요해 사용자가 직접 진행.
- Firebase SDK 버전(10.12.2)은 네트워크 제약으로 이 세션에서 직접 로드 테스트를 못 함 — 실제 배포 후 콘솔 에러 발생 시 버전 조정 필요할 수 있음.
